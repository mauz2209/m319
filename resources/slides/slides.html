if-then-else

In vielen Situationen soll der Hamster entscheiden, ob er etwas tun soll - unter welcher Bedingung. Diese Abfrage wird mit dem if-then-else-Konstrukt programmiert.


						void main () {
							if ( vornFrei ()) { // bedingte Anweisung
								vor ();
								linksUm ();
							}
							if ( kornDa () && vornFrei ()) { // Alternativanweisung
								nimm ();
								vor ();
							} else {
								linksUm ();
							}
						}

Um zu entscheiden, welche Anweisung ausgeführt werden soll, verwenden wir Testbefehle. Diese funktionieren wie die Hamster-Befehle, die Sie bereits kennengelernt haben, jedoch geben Sie einen Wahrheitswert (true/false) zurück.

  • vornFrei(): Gibt true zurück, wenn vor dem Hamster keine Wand ist.
  • kornDa(): Gibt true zurück, wenn ein Korn unter dem Hamster liegt.

Schleifen (loops)

Soll der Hamster etwas so lange tun, wie eine bestimmte Bedingung gilt, verwenden wir Schleifen (wir nennen sie auch: loops).


						void main () {
							macheEtwasMehrmals ();
							macheEtwasMehrmalsMitDo ();
						}
		
						void macheEtwasMehrmals () {
							while ( vornFrei ()) { // while - Schleife
								vor ();
							}
						}
		
						void macheEtwasMehrmalsMitDo () {
							do { // do - Schleife
								vor ();
							} while ( vornFrei ());
						}

Prozeduren

Prozeduren sind eine Möglichkeit, Code (Anweisungen) zu gruppieren. Dadurch wird:

  • der Code besser lesbar.
  • verhindert, dass Code doppelt geschrieben werden muss (duplicate code).

Das main-Konstrukt ist eine spezielle Prozedur, welche beim Start eines (Java-)Programms automatisch ausgeführt wird. Es ist also der Einstiegspunkt in das Programm.
Die Befehle, die der Hamster bereits kennt (z.B. vor()) sind ebenfalls procedures. Diese sind im Framework schon vorprogrammiert.


	void rechtsUm () { // Prozedurdefinition
		linksUm ();
		linksUm ();
		linksUm ();
	}

	void main () { // main - Prozedur
		rechtsUm (); // Prozeduraufruf
		nimm ();
	}

Functions

Functions sind Prozeduren, die einen Rückgabewert haben. Die Vorteile entsprechen denen von Prozeduren. Zusätzlich können Functions aber z.B. in if- und while-Statements verwendet werden: 


	boolean linksFrei () { // Definition einer booleschen Funktion
		linksUm ();
		if ( vornFrei ()) {
			return true ; // boolesche return - Anweisung
		} else {
			return false ; // boolesche return - Anweisung
		}
	}
	void main () {
		while ( vornFrei () && ! linksFrei ()) { // Aufruf einer booleschen Funktion
			vor ();
		}
		if ( linksFrei ()) { // Aufruf einer booleschen Funktion
			linksUm ();
			vor ();
		}
	}

Das ist eine imperative Hamsteraufgabe! Gegeben ist das nachfolgende Territorium.

  • Auf der Kachel, auf der sich der Hamster befindet, liegen Körner in unbestimmter Anzahl, aber maximal 255.

Aufgaben

  1. Der Hamster soll alle aufgenommenen Körner auf dem letzten Feld ablegen.
  2. Der Hamster soll alle aufgenommenen Körner auf dem zweitletzten Feld ablegen, wobei die Länge des Territoriums auch variieren können soll.
  3. Der Hamster soll auf jedem Feld gleich viele Körner ablegen. Wenn ein Rest übrig bleibt, soll er diese auf dem ersten Feld ablegen.
  4. Challenge: Der Hamster ist faul. Lösen Sie diese Aufgabe so, dass der Hamster möglichst wenige Befehle ausführen muss.
  5. Der Hamster soll die Anzahl aufgenommener Körner binärkodiert wieder hinlegen (d.h., von dezimal nach binär umrechnen):
    • Eine leere Kachel entspricht dem Wert 0.
    • Ein Korn auf der Kachel entspricht dem Wert 1.

Aufgabe: Mulde durchschreiten

Ein Hamster steht mit Blickrichtung nach rechts ohne Körner im Maul vor einer unregelmässigen Mulde unbekannter Tiefe (Beispiele siehe Bild).

Der Hamster bekommt die Aufgabe, die Mulde zu durchschreiten. Sobald er dies geschafft hat, d.h. sobald er auf eine Ebene gelangt, die dieselbe Höhe aufweist wie die Ausgangsposition des Hamsters, soll er stehen bleiben.

Aufgabe: Many lines

Das ist eine imperative Hamsteraufgabe! Gegeben ist das nachfolgende Territorium.

Aufgabe

  • Der Hamster befindet sich wie abgebildet und mit gegebener Blickrichtung auf dem Territorium.
  • In der unteren linken Ecke liegt ein Korn.
  • Der Hamster verfolgt das Ziel, das Korn zu finden und aufzunehmen. Dann endet das Programm.
  • Der Hamster soll den Weg auch dann noch finden, wenn ein Durchgang horizontal verschoben wird.

Pro-Aufgaben (freiwillig)

  1. Der Hamster soll den kürzesten Weg zu seinem Ziel nehmen.
  2. Der Hamster darf ausschliesslich jeden zweiten Durchgang ab seinem aktuellen Standort nehmen. Auch jetzt soll er den kürzesten Weg nehmen.
  3. In der linken unteren Ecke liegen jetzt n Körner (1 <= n <=4). Der Hamster soll diese Körner aufnehmen und so viele "Stockwerke" hochsteigen, wie er Körner aufgenommen hat. Dann soll er ganz nach links laufen.

Versionskontrolle mit Git

Wichtigste Gründe für ein Versionskontrollsystem

  • Versionierung von Files: Vergleichen, gelöschten Code finden, Historie einsehen, ...
  • Im Team arbeiten: Zeitgleich an denselben Files arbeiten, Änderungen an gemeinsamen Files zusammenführen, ...

Wie geht das?

  • Zentraler Server (remote repository)
  • Lokales repository mit tracking der Änderungen
  • "Merge"-Funktion, um Änderungen von verschiedenen Personen an denselben Files zusammenzuführen

Git-Flow

  • Git kennt remote und local Repositories. Ein remote repository wird auf ihren lokalen Client gecloned.
  • Repositories haben branches. Diese finden Sie dann natürlich auch im local repository.
  • Eine Änderung eines files bringen Sie mit commit auf einen branch.
  • Die Änderungen eines local repositories pushen Sie auf das remote repository.
  • Die Änderungen eines remote repositories pullen Sie auf das local repository.

Hamster-Evolution

Hamster-Evolution

Also nochmal: Der Hamster, ein Objekt (Instanz) einer Klasse

Imperatives Modell

  • Es gibt einen Hamster, der automatisch initialisiert wird.
  • Der Hamster kennt 4 vordefinierte Befehle.
  • Der Hamster hat keinen Namen (braucht er auch nicht, er ist ja alleine).

Objektorientiertes Modell

  • "Hamster" ist nicht mehr ein Objekt, sondern eine "Art" (also eine Definition oder Beschreibung von Objekten).
  • Unser Standard-Hamster muss initialiert (erstellt) werden; und es können weitere Hamster erstellt werden.
  • Jeder Hamster bekommt einen Namen - der "Name" ist der Zeiger/Pointer auf den Speicherort eines Hamsters (vgl. Variable).
  • Hamster (also die ganze Art) können mit Fähigkeiten und Attributen erweitert werden.
  • Man kann Subtypen (Unterarten) von Hamstern erstellen, z.B. "Goldhamster", mit anderen Fähigkeiten und Attributen.

Der objektorientierte Hamster im Code

Initialisierung des Standard-Hamsters

		Hamster pinky = Hamster.getStandardHamster();

Erstellen und initialisieren eines zweiten Hamsters:


		Hamster brain = new Hamster ();
		brain.init (3 , 4 , Hamster.NORD , 5);

Einen Hamster befehligen:


		if (brain.vornFrei()) {
			brain.vor();
		}
